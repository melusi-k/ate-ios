# Ate architecture and design records

Designs explain intent and boundaries. They do not certify implementation or acceptance. Read their status, source baseline and unresolved decisions before using them as a build plan.

| Document | Scope | State |
| --- | --- | --- |
| [Design template](DESIGN_TEMPLATE.md) | Reusable structure for substantial changes | Proposed template |
| [Intelligence Foundation](ATE_INTELLIGENCE_FOUNDATION.md) | Existing system actions/model paths; scoped-context architecture direction and open decisions | Proposed discovery/design; first slice unselected |
| [Food Journal contract](../product/FOOD_JOURNAL.md) | Journal/meal identity, privacy, canonical store and migration | Contains a dated historical baseline; read [the drift report](../reviews/2026-11-05_DESIGN_DRIFT.md) before relying on its current-state claims |

Use [design review](../DESIGN_REVIEW.md) and the existing lifecycle for approval. Add focused decision records when decisions exist; do not create empty ADRs or mark an option accepted without its decision source. Link acceptance and evidence to the owning issue/QA matrix rather than making another checklist here.
